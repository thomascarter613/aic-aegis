# Branching and PR Policy

How changes should flow.

---

## Purpose

Branching and PR Policy defines how changes enter the repository.

---

## Recommended Flow

1. Create issue or work packet.
2. Create branch from `main`.
3. Implement scoped change.
4. Run tests and checks.
5. Update docs.
6. Open PR.
7. Review against acceptance criteria.
8. Merge after approval.

---

## Branch Naming

Examples:

* `docs/wiki-product-overview`,
* `feat/run-envelope`,
* `feat/tool-broker`,
* `fix/policy-decision-record`.

---

## PR Requirements

PRs should include:

* summary,
* linked issue/work packet,
* tests,
* docs updates,
* risk notes,
* acceptance checklist.

---

## North Star

Branching and PR policy keeps changes traceable.
